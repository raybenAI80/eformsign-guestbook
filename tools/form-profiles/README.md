# 서식별 좌표 프로필

작성 프레임 안의 서식은 `<canvas>` 로 그려지고 입력칸이 DOM 으로 노출되지 않는다 —
**입력칸 위치를 자동으로 찾아낼 방법이 없다**(2026-09-16 실측: 컴포넌트 후보 요소 0건,
뷰어 JS 에 component/field API 0건, 노출된 `input` 은 뷰어 툴바 버튼뿐).

그래서 값을 실제로 입력해 보는 검증에는 서식마다 좌표를 적어 둔다.
`verify-kiosk.mjs --template <formId>` 는 이 폴더의 `<formId>.json` 을 **자동으로** 읽는다.

```json
{
  "consent":  [38, 196],
  "continue": [708, 175],
  "name":     [490, 496],
  "org":      [520, 558],
  "send":     [686, 973],
  "popup1":   [606, 639],
  "popup2":   [606, 716],

  "purpose":   [333, 679],
  "zoomOut":   [663, 151],
  "signField": [512, 374],
  "blankClip": [322, 470, 350, 52]
}
```

- 뒤쪽 네 개는 **이탈 매트릭스**(`probe-abandon-matrix.mjs`)만 쓴다 —
  `purpose` = 아무 체크박스 하나, `zoomOut` = 뷰어 축소(−) 버튼(서식과 무관한 툴바),
  `signField` = 최소 배율(20%)에서 보이는 서명 칸, `blankClip` = `[x, y, width, height]`
  형태로 「빈 서식인가」를 픽셀 비교할 잘라내기 영역(첫 입력칸을 감싸면 된다).
  서명 칸이 없는 서식이면 그 케이스는 의미가 없으니 `KIOSK_CASES` 로 골라 돌린다.
- 파일 이름은 **서식 ID + `.json`** 이다. 운영 중인 서식 ID 는 공개 원본에 올리지 않는다 —
  이 폴더에는 예시만 두고, 자기 서식 프로필은 각자 만들어 쓴다.
- 좌표계 = 768×1024 태블릿 뷰포트. 헤드리스 크롬을 이 크기로 띄워 잡는다.
- 값 입력이 목적이 아니면 **`--notype` 을 쓰는 것이 기본이다** — 프로필 없이도 어떤 서식에서든 동작한다.
- `name`/`org` 는 이름과 무관하게 **첫 번째·두 번째 입력칸**이라는 뜻일 뿐이다. 서식에 입력칸이
  하나뿐이면 `org` 를 `name` 과 같게 두거나 `--notype` 을 쓴다.
- 잡는 법: `--notype` 으로 한 번 돌려 `evidence/A-r1-2-editable.png` 를 만들고 그 그림에서
  누르고 싶은 칸 가운데 픽셀을 읽는다. 실행 시 `COORDS {...}` 한 줄로 적용값이 찍힌다.
