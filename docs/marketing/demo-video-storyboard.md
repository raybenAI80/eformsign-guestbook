# 이폼사인 방명록 — 실제 화면 편 스토리보드 (v1 확정 2026-10-03)

대상 화면: https://eformsign-guestbook-test.vercel.app/ (누적형 방명록 D v8 · 10행 1쪽 · 헤더 밴드 「방문자 기록부」 · 「처음부터 다시」 · 운영시간 하루 단위 새 장)
상태: **v1 확정.** 카피 표(§2) = 사용자 확정본, 변경 시 TTS·길이 재생성.

## 0. 이 편의 자리

| | 홍보편(v3.x, 완성 단계) | **실제 화면 편(이 문서)** |
|---|---|---|
| 목적 | 문제 인식 → 이폼사인으로 해결된다는 약속 | 약속이 **실제로 어떻게 돌아가는지** 화면으로 증명 |
| 소재 | 생성 이미지 + 실캡처 합성 + 3D 손 층 | **실캡처 위주**(태블릿 768×1024 실기 렌더 + 이폼사인 PC 문서함), 사람 장면 최소 |

적용 규칙(정본은 memory·볼트): 헤드라인에 「태블릿·설치·무인 키오스크」 금지 · 가격·「무료」 금지 · 「행사·이벤트·전시」 금지 · 화면은 **이폼사인 정식 UI 와 이폼사인이 만든 문서만**(report.html·설정 마법사·카운트다운 덮개는 소구점 금지, 장치로만) · 자막 한 줄 15~25자, 조사는 앞 어절과 같은 줄 · 로고 PNG 불변.

## 1. 한 줄 약속

> 열 명이 차례로 써도 **앞사람 정보는 보이지 않고**, 문서는 **하루 한 장**으로 이폼사인에 쌓인다.

이 편이 홍보편과 달리 보여 줄 수 있는 것은 **「행 가림」과 「한 장 누적」** 두 가지다. 둘 다 실제 화면이라야 믿긴다.

## 2. 장면표 (8장면, 가안 52초)

시간은 가안. 실제 길이는 `tools/tts.mjs` 가 나레이션에서 역산한다.

|---|---|---|---|---|---|---|
| 1 | hook | 0–4 | 검은 바탕 → 태블릿 화면 페이드인(헤더 밴드 「방문자 기록부」가 먼저 읽히는 배율) | 「수기 방명록을 이폼사인으로 바꾸면」 / 「실제 화면은 이렇습니다」 | 수기 방명록을 이폼사인으로 바꾸면, 실제 화면은 이렇습니다. | BGM 인(홍보편 track 변주) |
| 2 | arrive | 4–10 | 태블릿 전체. 열린 행 1개만 입력 가능, 나머지 행은 빈 칸. 손 층(hand-03 재사용)이 성명 칸으로 들어옴 | 「방문하신 분은」 / 「열려 있는 한 줄만 적습니다」 | 방문하신 분은 열려 있는 한 줄에 이름과 연락처, 방문 목적만 적습니다. | 탭 효과음 |
| 3 | fill | 10–20 | 성명·연락처 입력 → 방문 목적 체크 1개 → 서명 획 → 「전송」 안내 띠 점등 → 전송 탭. 입력값은 가상 인물 | 「적고, 체크하고, 서명하면」 / 「끝입니다」 | 적고, 체크하고, 서명하면 끝입니다. 서명이 끝나면 전송 버튼이 어디 있는지 화면이 알려 줍니다. | 탭 3회 + 서명 스크래치 |
| 4 | next | 20–28 | 전송 직후 화면이 **스스로 처음으로 돌아감**(「처음부터 다시」 장치는 잠깐만). 두 번째 방문자 시점: 앞 행이 가려져 있음. 좌우 분할(SplitScreen 재사용): 왼쪽 첫 방문자가 쓴 행, 오른쪽 두 번째 방문자가 보는 화면 | 「다음 분에게는」 / 「앞사람 정보가 보이지 않습니다」 | 다음 분에게는 앞사람 이름도 연락처도 보이지 않습니다. 같은 한 장인데도요. | 짧은 「휙」 복귀음 |
| 5 | stack | 28–36 | PC 이폼사인 문서함(정식 UI). 문서 **1건**이 보이고, 열면 10행이 차례로 채워진 서식(완료 PDF 미리보기 — 완료본에는 모든 행이 보인다) | 「열 명이 써도」 / 「문서는 하루 한 장」 | 열 분이 써도 문서는 하루 한 장입니다. 이폼사인 문서함에 그대로 쌓입니다. | 카드 착지음(stack-shimmer 재사용) |
| 6 | manage | 36–44 | 문서함 검색(이름으로) → PDF 미리보기 → 다운로드. 운영시간이 지나면 다음 날 새 장이 열린다는 건 **자막 각주 한 줄**로만 | 「찾고, 열고, 내려받기까지」 / 「이폼사인 문서함에서」 | 찾고, 열고, 내려받기까지 이폼사인 문서함에서 끝납니다. | 탭 |
| 7 | branch | 44–50 | 홍보편 Branch 재사용(방명록 → 계약·동의·접수) | 「방명록은 시작일 뿐」 / 「계약·동의·접수도 같은 이폼사인」 | 방명록은 시작일 뿐입니다. 계약도, 동의도, 접수도 같은 이폼사인입니다. | 전환음 |
| 8 | cta | 50–54 | 홍보편 CTA 재사용(로고 PNG + 패널). 보조 링크 한 줄: 방명록 안내 페이지 | 「지금 이폼사인을 체험해 보세요」 / www.eformsign.com | 지금 이폼사인을 체험해 보세요. | cta-reveal |

## 3. 캡처 계획 (실측 자산)

| 자산 | 출처 | 방법 | 비고 |
|---|---|---|---|
| 태블릿 빈 명부·입력 중·서명·전송 띠 | 테스트 사이트(위 URL) 768×1024 | 데모 저장소의 `tablet-step` CLI 로 단계별 결정적 캡처(`--attach` 는 iframe 여백 가산) | 🔴 동의서 체크는 오케스트레이터가 직접. efstest 시험 문서는 끝나면 소프트 삭제 |
| 두 번째 방문자 화면(앞 행 가림) | 같은 문서 2번째 단계 | 1명 전송 완료 후 다시 열어 캡처 | 행 가림 = SetVisible(false). 가려진 상태는 **작성 화면에서만** 보인다 |
| 문서함 1건·10행 완료본 | 이폼사인 PC 문서함(efstest) | 10명분 `--fill` 로 채운 문서의 문서함 목록·미리보기·PDF 캡처 | 🔴 완료 PDF 는 SetVisible 미적용 → 모든 행이 보이는 게 정상(5번 장면 의도와 일치) |
| 손 층 | 홍보편 hand-03.png + hand-path 재측정 | `tools/measure-hand-path.py` 를 새 캡처 차분에 다시 돌림 | 손 모션 게이트 `check-hand-motion` 그대로 |
| 기기 바탕 | 홍보편 gen-03-plate(손 없는 바탕) 재사용 또는 화면만 평면 | 결정 ⑤ | 바탕을 재사용하면 screenQuad 재측정 불필요 |
| 나레이션 | edge-tts 인준 +0% | `tools/tts.mjs` | 홍보편과 같은 목소리로 시리즈감 |

함정(볼트 정본): 템플릿 기본값 3종(본인확인·인증서 서명·외부 완료 알림) 해제 확인 · `hide_request_popup` false 강제 · 모바일 뷰어 좌상단 버튼이 로고를 가림(캡처 배율 주의) · 외부 메일 미발송은 정상.

## 5. 확정 뒤 레인 순서

1. 카피 표 확정 → `script.ts` 분기(새 컴포지션 Demo52, SceneId 추가) → TTS → scene-durations.
2. 캡처 레인(Opus): tablet-step 단계 캡처 + 문서함 캡처 + 손 경로 재측정. 동의 클릭은 오케스트레이터.
3. 조립 레인(스택은 ②): 장면 8개, 게이트 = check-script(쉬운 말)·check-hand-motion·check-shot-framing·check-mix·check-linebreak(자막).
4. 판정: 스틸 원본 크기 + 200% 크롭(자막·손·화면 경계), 사용자 판정 → 수정 → 렌더.
5. 완료 정의: 볼트 write-back(새 함정) · 스킬 `eformsign-kiosk` 에 「영상 캡처 절차」 링크 · work-tooling 게이트.
