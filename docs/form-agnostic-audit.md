# 서식 가정 감사 — 이 제품이 서식에 대해 무엇을 가정하는가

> **IT 담당자용 문서입니다. 고객은 읽지 않아도 됩니다.**

작성 2026-09-16. 기준: **이 제품은 방문자 기록부 전용 화면이 아니라, 고객이 어떤 서식이든 붙이는
범용 무인 작성 화면이다.** 그러므로 코드·도구·문서 어디에도 「항목 이름이 무엇이다 / 항목이 몇 개다 /
서명이 있다 / 날짜가 있다 / 체크박스가 있다 / 한 장짜리다」 라는 가정이 남아 있으면 안 된다.

감사 범위는 `kiosk-product` 전체(화면·설정 마법사·빌드·리포트 API·검증 도구·문서)다.
판정은 세 가지다.

| 판정 | 뜻 |
|---|---|
| **중립** | 서식 구조를 전혀 모른다. 항목을 바꿔도 손댈 것이 없다 |
| **고쳤음** | 가정이 있었고 이번에 없앴다 |
| **남김(의도)** | 가정이 남아 있지만 그래야 하는 이유가 있다. 그 이유와 회피 수단을 함께 적는다 |

### 왜 「첫 입력칸 자동 탐색」이 아닌가 — 부정 결과

작성 프레임은 다른 도메인의 iframe 이고, 그 안의 OZ 뷰어는 서식을 `<canvas>` 로 그린다.
2026-09-16 실측에서 **입력칸이 DOM 으로 전혀 나오지 않았다**(컴포넌트 후보 요소 0건, 뷰어 JS 에
component/field API 0건, 노출된 `input` 은 뷰어 툴바 버튼뿐). 그래서 위치를 자동으로 찾아낼 방법이
없다. 서식 중립의 실제 수단은 **`--notype`(값 입력 생략)** 이고, 값을 넣어 봐야 하는 검증에만
서식별 좌표 프로필을 둔다.

| 서식 B — 항목 변경본 | 위에서 1개 추가·1개 이름 변경·1개 삭제 | 전송 `8cf964faab844d4bb9a88ead6b48034a` · 빈 서식 복귀 |
| 서식 C — 만족도 설문 | 라디오 3 + 자유 입력 1. **서명 없음·날짜 없음·이름 칸 없음** | 전송 `fd8c859ad9614ae6ad782d0748f69381`(값 없이) · `56f25a2c5d4f41a4a1093504e80df00d`(값 입력) · 빈 서식 복귀 |

